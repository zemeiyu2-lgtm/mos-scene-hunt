## 3. 已发现的国际化缺口

- `app/layout.tsx` 的页面 metadata 仍以中文为主。
- 首页 `app/page.tsx`、共享 UI `components/ui.tsx`、底部导航 `components/tab-bar.tsx` 等页面/组件有直接写入的中文界面文字。
- `components/providers.tsx` 与 `lib/storage/index.ts` 当前设置中没有界面语言字段。
- 目前没有确认存在统一的界面文案字典或全局语言切换入口。
- 游戏包有独立 `language` 字段，这是内容语言，不应直接拿来决定整个应用界面语言。
- 当前还未完成全量字符串清点；实施前需继续检查首页、地图、情境、挑战、奖励、任务、背包、创作/导入导出和错误状态。

## 4. 已发现的体验机会

- 首页应优先让新玩家开始游戏、让老玩家继续进度；不应一次展示过多技术信息。
- 地图是主要游玩界面；需要优先确保目标、距离、进度和下一步行动易懂。
- 答题当前共用三种输入类型。第一批以布局、线索视觉、选择卡片和即时反馈为主，不立即增加复杂的小游戏引擎。
- 奖励页需要持续区分“未获得”和“已获得”，且不能只用文案暗示不存在的输入功能。
- 统一视觉应通过少量共享组件、设计 token 和轻量素材完成，不应先导入大型 UI 框架或图像库。

## 5. 地域主题建议的最小技术路径

- 先确定游戏包可选的主题标识/配置，不直接用 GPS 结果强制改主题。
- 初期主题只包含少量色彩、图标和可选背景素材；默认主题必须始终可用。
- 主题配置与游戏题材分离：同一地点可玩校园寻宝、历史探索、自然观察或科幻主题。
- 国家/地区只作为设计参考，不在第一版开发全球文化数据库。
- 增加主题字段前，需核对 schema 的 `additionalProperties` 约束、内容包导入/导出和旧包兼容；缺失字段必须回退默认主题。

## 6. 建议的实施批次

### 批次 1：轻量视觉与答题体验
范围：首页、地图 HUD、挑战反馈、奖励页；不改游戏引擎、坐标、存档格式。
验收：现有正确/错误答题、奖励状态、下一站和最后一站流程不回归。

### 批次 2：英中语言基础
先增加可持久化的 `en` / `zh-CN` 界面语言设置和集中式文案字典；再逐页替换硬编码界面文字。
验收：页面切换语言完整；内容包内容不被自动翻译；切换前后存档、GPS、背包不变；默认英文只影响新安装/无偏好用户，不能无条件覆盖已保存偏好。

### 批次 3：最小地域主题
先实现默认通用主题和一个经核对的菲律宾主题；不做自动地理反向编码依赖，设计者可明确选择。
验收：主题缺失回退默认；切换主题不影响任务、坐标或存档；素材失败不阻止游戏运行。

### 批次 4：品牌名称评估
品牌确定后再修改可见名称、metadata、PWA 标题、图标和分享文案；避免在语言/视觉结构未稳定前反复更名。

## 7. 修改安全门槛

- 在独立分支开发；不合并、不部署正式版，除非通过相应验收。
- 每批尽量控制文件范围，先改共享机制，再改页面，避免一次性全站替换。
- 运行项目现有 `npm run typecheck`、`npm test`、`npm run build`；按变更范围运行 `npm run test:acceptance`。
- 云端构建 READY 不替代真实手机测试。
- 不修改 `content/*.json` 的坐标和题目来配合视觉改版。
