# MOS Scene Hunt 主题预设：安全实施提案

状态：设计提案，尚未作为用户可选功能发布。

## 目标

让不同游戏有自己的氛围，同时保持玩家熟悉的操作方式。主题只改变呈现，不改变游戏规则或数据。

## 第一轮候选

| 预设 | 视觉气质 | 适用场景 | 边界 |
|---|---|---|---|
| Natural Expedition（自然探索） | 清爽、户外、森林绿与地图蓝 | 默认主题、校园与公园探索 | 保持现有浅色视觉基线 |
| Story Journal（故事手记） | 纸张感、暖白、柔和墨绿与少量赭色 | 叙事、文化导览、亲子故事 | 不使用低对比度仿旧文字，不模拟复杂纸张纹理 |
| City Detective（城市侦探） | 清晰网格、石板灰、强调色用于线索 | 城市观察、建筑与解谜 | 强调色不能替代状态文字；地图定位仍用独立的地图语义色 |

第一轮只评估这三个方向。暂不同时加入深色模式、动画主题或大量装饰选项，以免增加维护与验收成本。

## 架构边界

主题只能是 presentation-only（仅呈现层）设置：

- 允许改变：CSS 颜色令牌、背景与边框、卡片视觉、装饰纹理、封面与图标的呈现方式。
- 不允许改变：GPS 定位、距离计算、触发半径、场景顺序、挑战答案、奖励逻辑、存档键、玩家进度、背包、游戏包 JSON schema、分享 URL/二维码协议。
- UI 语言与游戏内容语言继续分离。切换界面语言不能翻译或覆盖创作者写入的内容。
- 未选择主题时必须继续使用当前 Natural Expedition 视觉基线，不能要求旧游戏包迁移。
- 主题偏好若需持久化，应与游戏包和玩家进度分开保存；不能将主题字段直接塞进游戏包，除非未来经过单独架构审查和兼容性设计。
- 游戏创作者可为单个游戏选择呈现风格时，接收者的默认体验和旧分享链接必须保持可预测；不得因主题选择改变链接所携带的核心游戏内容。

## 建议实施顺序

1. 先建立主题令牌映射表，确认它只引用 CSS 变量，不触碰 gameplay schema。
2. 用一个明确的根级 presentation 属性或 class 切换令牌；默认值不设置时等同现有主题。
3. 先做视觉样例和窄屏截图对比，再接入真实页面。
4. 为默认主题、另外两个主题和中英文分别检查文本对比度、长词换行、按钮触控区域。
5. 跑 TypeScript、单元测试、生产构建和端到端验收。
6. 单独回归验证切换主题前后 GPS、游戏内容、存档、背包、进度与分享包完全不变。
7. 完成手机实测后再讨论是否将主题选择交给玩家或创作者。

## 验收清单

- [ ] 无主题设置的旧游戏仍使用当前默认视觉。
- [ ] 切换主题不会改变任何游戏内容或玩法数据。
- [ ] 英文与简体中文无裁切、重叠或横向溢出。
- [ ] 地图当前位置、目标、状态和距离仍清晰可辨。
- [ ] 主要触控目标至少 44 CSS px，主操作约 48 CSS px。
- [ ] 普通文本和控件状态有足够对比度，不能只靠颜色传达含义。
- [ ] 自动化验收全通过。
- [ ] 实际手机检查完成；在此之前不得声称真实设备验收通过。

## 当前决定

这份文件只定义安全边界和实施顺序，不代表主题切换功能已经实现。应先完成当前移动端视觉统一并验收，再单独实施主题令牌切换，避免把视觉润色与架构改动混在同一批次。
