# MOS Scene Hunt｜设计决策与交付清单

> 本文是项目持续更新的决策记录。状态只有在代码/预览证据支持时才更新，不以讨论或提交代码代替验收。

## 产品定位与不可丢失的原则

- **手机优先游玩，电脑辅助设计。** 玩家不应需要携带电脑。
- **轻入口、弱打扰、强体验。** 不用功能堆叠取代真实探索。
- **户外真实地点驱动。** 以获准、安全的开放区域为主，不强迫玩家进入室内。
- **核心循环：** 现实移动 → GPS 到达/现场观察 → 情境 → 玩家主动完成任务 → 反馈/奖励 → 解锁下一地点。
- **GPS 是辅助，不是唯一裁判。** 提供定位异常、权限拒绝和无法触发时的合理说明/恢复路径。
- **创作双路径：** 设计者可用 AI 生成初稿，也可用真实照片手工设计；最终进入同一编辑器。平台不自研 AI 模型，不把 AI 审核强塞进玩家游戏流程。
- **真实承诺与安全：** 奖励必须可兑现；事实与场地权限由设计者核实；不强迫拍照或收集个人信息。玩家临时照片默认不长期保存，尤其避免儿童、面部和个人信息。
- **数据诚实：** 当前本地保存只在本浏览器；不得声称已经具备云端保存、账号同步或跨设备自动同步。

## 交付门槛

不能仅凭 CI/部署状态宣布完成。对每个版本分别报告：
1. **已提交**：代码提交已存在。
2. **已部署**：预览平台状态 READY，并提供确切 URL。
3. **自动检查**：测试/构建实际结果。
4. **实际验收**：浏览器/手机真实操作结果。
5. **限制与未完成项**：尤其是本地存储、外链媒体、GPS 实测和跨设备分享。

## 推荐执行顺序

1. 修复明显 UI 缺陷并确认预览。
2. 验证 JSON 导入和结构错误反馈。
3. 将经典模板和照片转换为独立静态资源，确保内容包加载稳定。
4. 验证导入、编辑、保存、导出/分享。
5. 手机完成一轮模拟与一轮户外实测（GPS 坐标现场校准后）。
6. 再进行首页视觉精修、地图/任务联动和媒体库设计。

## 安全与发布边界

- 默认仅部署 Preview；不合并 PR、不部署 Production，除非用户明确授权。
- 不覆盖或删除用户已有游戏包/数据。
- 校园坐标只视为模板坐标，未现场核验前不可作为正式导航点。


## 分享链接：已明确的技术方案（2026-10）

- **现状**：将完整游戏 JSON（尤其是嵌入式 Base64 照片）直接放进 URL 会产生很长的链接；浏览器本地保存也不能让其他设备自动取得游戏。
- **二维码的作用**：方便扫描，不会缩短二维码所承载的长 URL。不得把“生成二维码”宣传成“短链接”。
- **正式短链接方案**：游戏发布时将游戏快照和媒体上传到项目自己的存储，生成随机分享 ID，玩家通过短路径打开；需支持版本快照、撤销/删除、大小限制和访问失败提示。
- **隐私边界**：不使用未经评估的第三方免费二维码/短链服务来上传游戏内容；不将私密草稿默认公开。
- **状态**：短链接后端与持久化存储尚未配置，不能声称已完成。当前交付优先让用户体验首页、创作器和 JSON 导入/导出；短链作为下一项独立实现与验收。
- **本轮视觉验收重点**：菲律宾热带色彩（海洋蓝、岛屿绿、茉莉花奶油白、日落金）、手机首屏层次、按钮可读性、窄屏不溢出；只改 Preview，不发布 Production。
