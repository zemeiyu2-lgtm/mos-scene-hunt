# MOS Scene Hunt｜云端架构与演进路线 V1.0

## 一、定位

MOS Scene Hunt 采用“设计端—云端—游玩端”三端分离架构。

核心原则：

> 云端负责管理、保存、审核、发布、分发；电脑负责设计；手机负责下载、定位与游玩。

当前阶段不建设完整多人云端，只冻结接口和数据边界，避免未来推倒重来。

## 二、三端职责

### 设计端

- 电脑优先，也支持手机基础设计。
- 导入 Word、Markdown、JSON。
- 设计地图、区域、场景、故事、任务、奖励。
- 自动验证。
- 导出 MOS Game Package。
- 保存到本机游戏库。

### 云端

未来使用 Supabase 作为业务云端。

负责：

- 用户与身份
- 游戏总库
- 游戏版本
- 投稿与审核
- 团队与权限
- 游戏资产
- 发布状态

GitHub 继续负责程序代码、官方模板和版本控制；Vercel 继续负责 Web App 部署与分发。

### 游玩端

- 手机优先。
- 从游戏中心下载游戏包。
- 下载后进入本机游戏库。
- GPS、场景、任务和奖励尽量本地运行。
- 首次下载后支持离线游玩。
- 普通玩家不需要理解云端、数据库或游戏设计器。

## 三、核心对象

未来云端不是“一个云盘文件夹”，而是游戏平台。

核心对象：

```
User
Organization
Membership
Game
GameVersion
GameSubmission
GameReview
GameAsset
```

游戏生命周期：

```
草稿 → 提交审核 → 审核中 → 已发布 → 下架
```

版本生命周期独立于发布状态。

## 四、游戏包是系统核心边界

无论内容来自：

- Word
- Markdown
- JSON
- 游戏设计器
- AI 辅助设计
- 云端编辑器

最终都必须转换成统一的 **MOS Game Package**。

关系：

```
Word ───────┐
Markdown ───┤
JSON ───────┤
设计器 ─────┼──→ MOS Game Package ──→ 本机游玩
AI ─────────┤                    └──→ 云端发布
云端编辑器 ─┘
```

这样可以保证设计工具变化时，游玩引擎不需要跟着重写。

## 五、当前实现

当前 V0.x 使用：

```
GitHub
  ↓
Vercel
  ↓
官方游戏目录 + 游戏包
  ↓
手机/电脑下载
  ↓
本机游戏库
```

当前云端游戏中心是“静态云端目录 + 游戏包分发”，不是完整的多人数据库。

目前不提供：

- 用户注册系统
- 用户投稿
- 在线数据库
- 团队空间
- 在线审核后台

这些属于未来 Supabase 阶段。

## 六、未来 Supabase

当出现以下需求时再启用 Supabase：

- 多人设计
- 用户投稿
- 管理员审核
- 私有游戏
- 团队共享
- 游戏版本历史
- 云端备份
- 游戏权限

建议的数据关系：

```
organizations
  └── memberships
        └── users

games
  └── game_versions
        └── game_assets

games
  └── game_submissions
        └── game_reviews
```

普通玩家可以匿名或轻量身份下载公开游戏；复杂权限只对设计者和管理员开放。

## 九、离线原则

游戏包下载完成后，核心游玩不依赖持续网络。

因此：

- 游戏内容必须可本地保存。
- GPS 与触发逻辑必须本地运行。
- 任务与奖励必须本地运行。
- 网络恢复后再考虑同步进度或统计。

不要让户外游戏因为网络波动而中断。

## 十、建设顺序

### 当前阶段

1. 冻结游戏包格式。
2. 稳定 Word / Markdown / JSON 导入导出。
3. 稳定本机游戏库。
4. 稳定官方游戏中心。
5. 做好云端适配层。

### 下一阶段

在真实用户开始设计和提交游戏之后，再建设：

1. Supabase 项目。
2. 用户身份。
3. 游戏数据库。
4. Storage。
5. 投稿。
6. 审核。
7. 发布。
8. 版本管理。

### 更成熟阶段

再加入：

- 团队空间
- 协作设计
- 云端备份
- 在线编辑
- 使用统计
- 游戏评分
- 游戏市场

## 十一、架构原则

1. **游戏包优先**：所有设计工具最终都输出统一游戏包。
2. **本地优先游玩**：云端不可用不应阻止已经下载的游戏。
3. **云端管理而非云端依赖**：云端管理游戏，手机不依赖持续联网。
4. **设计与游玩分离**：玩家不需要进入设计器。
5. **官方与用户内容分离**：官方游戏、用户游戏、团队私有游戏分别管理。
6. **版本不可覆盖历史**：正式发布后保留版本。
7. **审核后发布**：用户提交不等于公开。
8. **普通人不感知复杂架构**：复杂性留在平台内部。

## 十二、最终目标

MOS Scene Hunt 最终不是一个“GPS 小游戏网页”，而是一套：

> **可以设计、发布、下载、管理和游玩的真实场景游戏平台。**

其中 MOS Game Package 是连接设计、云端与手机的核心标准。
