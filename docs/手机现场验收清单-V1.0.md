# MOS Scene Hunt 手机现场验收清单 V1.0

用途：把自动化测试与真实手机验收分开记录。完成前不要把预览版称为正式版。

## A. 分享链接与二维码（至少两部手机）

- [ ] 设计手机打开预览版，创建或选择一个已设置真实坐标的游戏。
- [ ] 点击“发布并分享给朋友”，确认系统分享面板可用；取消面板后，页面仍保留链接和二维码。
- [ ] 如果二维码显示，调亮屏幕，用另一部手机的相机或微信扫一扫。
- [ ] 接收手机打开后，核对游戏标题、站点数量、站点名称与创建端一致。
- [ ] 接收端不登录、不依赖创建手机存档；关闭创建端后，接收端仍能加载这份游戏。
- [ ] 在接收端刷新页面，再核对一次标题和站点内容。
- [ ] 若游戏过大、二维码不显示，确认页面明确提示改用分享链接，不出现空白二维码。
- [ ] 修改创建端游戏并重新发布；确认新链接对应新版本，旧链接不会被误认为自动更新。

记录：创建手机型号/浏览器 ______；接收手机型号/浏览器 ______；结果/问题 ______。

## B. GPS 权限恢复与持续定位

- [ ] 首次打开“GPS 现场测试”，允许浏览器定位，等待出现真实坐标和精度。
- [ ] 在浏览器站点设置中暂时拒绝定位，返回页面确认显示可理解的错误和重试入口。
- [ ] 再到站点设置中允许定位，回到页面点击“重新获取定位”。
- [ ] 确认不只是出现一次坐标；等待移动一小段距离或重新定位，读数/地图上的玩家标记仍会更新。
- [ ] 关闭模拟定位，确认页面标明“真实设备读数”，而不是模拟位置。
- [ ] 到室外开阔处测试；记录定位精度，不把手机显示的精度估算当作真实误差保证。

记录：手机/浏览器 ______；权限拒绝后恢复是否成功 ______；精度读数 ______。

## C. PWA 与离线行为

- [ ] 保持联网打开首页、游戏选择页、地图页、任务页和背包页，等待 Service Worker 激活。
- [ ] 打开一份游戏内容，确认内容包已成功加载。
- [ ] 在地图上浏览目标周边，让需要的地图瓦片先加载一次。
- [ ] 开启飞行模式或断开网络，再刷新已访问过的游戏页面。
- [ ] 确认已缓存的应用页面和游戏内容仍可打开；若页面未缓存，确认显示清楚的离线提示而非白屏。
- [ ] 确认离线时地图只显示先前缓存过的瓦片；未缓存区域出现空白瓦片是预期限制，不代表整张地图已离线下载。
- [ ] 在允许定位的手机上测试离线 GPS。定位硬件与系统行为因设备而异，需记录实际结果。
- [ ] 恢复网络后刷新，确认页面恢复正常且已保存的游戏进度仍在。

边界说明：当前离线策略会缓存应用外壳、访问过的内容和部分地图瓦片；这不等于完整离线地图包，也不保证第一次打开时完全离线可用。

## D. 手机端完整游玩流程

- [ ] 在 360–430 CSS 像素宽的手机视口检查首页、选择页、地图、任务、背包无横向溢出。
- [ ] 从分享链接进入游戏，确认进入的是分享内容，而不是本机上另一个游戏。
- [ ] 在户外用真实 GPS 进入触发范围，确认站点解锁；离开触发范围再回来，流程仍合理。
- [ ] 完成一个挑战，确认奖励和进度保存；刷新后进度仍存在。
- [ ] 测试过程中确认按钮不会被底部导航、系统浏览器工具栏或屏幕边缘遮挡。
- [ ] 只在安全、可通行的区域走动；不为触发游戏进入道路、限制区域或危险地点。

## 验收结论

- 自动化 CI：以对应 GitHub Actions 运行结果为准。
- 预览部署：以对应 Vercel deployment 状态为准；预览版不是正式发布。
- 真实手机：只有实际完成以上项目并记录设备/浏览器，才可标记为“实机通过”。
