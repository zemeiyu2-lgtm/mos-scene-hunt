# 情景编辑功能说明（第一批）

## 目标
在原有设计流程内加强情景编辑，不另造一套复杂流程。AI 快速生成和人工精细设计共用同一编辑器；AI 不是必需步骤，设计者始终可以逐项修改。

## 当前改进
- 情景内容：分别编辑到达后故事、前往地点时的提示、玩家任务指令。
- 现场图片：使用媒体编辑器添加真实地点照片；题目图片可在题目区域单独添加。浏览器支持时，上传图片会缩放至最长边不超过 1600 像素，并尝试以 JPEG 质量 0.8 压缩；如果压缩结果没有更小或浏览器不支持，则保留原文件。文档类资料不做图片压缩。
- 题型：支持选择题、文本答案题、关键词题。
- 答案：选择题编辑选项和正确答案；文本/关键词题每行填写一个可接受答案。
- 反馈：编辑卡住时的提示和答对后的故事反馈。

## 设计者操作顺序
1. 选择一个场景。
2. 写下玩家到达后会看到的情景。
3. 添加现场真实照片。
4. 写清楚玩家要做什么。
5. 选择题型，填写问题和答案。
6. 添加提示与答对后的反馈。
7. 设置奖励线索。
8. 保存并进入手机试玩，检查玩家实际看到的内容。

## 设计原则
- 文字简单直接，全年龄玩家都能理解；避免长篇文学化叙述。
- 题目尽量与现场实物、照片、标志或故事有真实关系。
- 不强制玩家拍照或收集无关人员的个人信息。
- 游戏任务原则上全部在开放、安全、获准使用的户外区域完成，不要求进入建筑物。
- AI 生成内容必须由设计者检查事实、答案、现场安全和奖励兑现条件。
- 图片编辑可用不代表导入、导出和分享链路已完整验收，必须单独测试。

## 当前边界与已知风险
- 当前分享采用自包含链接：完整游戏包经 JSON 序列化、gzip 压缩后写入 URL 片段，不依赖账号或服务器存储。
- 图片和文档由媒体编辑器读取为 Data URL，并随游戏包一起保存。图片上传时会尝试缩放和压缩，能减少照片体积，但不能保证所有图片都变小；文档仍按原文件嵌入。gzip 对已压缩照片通常只能有限压缩，多张照片或 PDF 仍可能让分享链接过长，部分聊天软件、浏览器或二维码无法可靠承载。
- 目前不能把“复制游戏 JSON”视为已完成 JSON 导入功能；若编辑器没有对应导入入口，JSON 导入仍是待补功能。
- 预览部署成功只证明应用已构建并部署，不代表已完成手机端端到端验收。本轮尚未有可核实的自动化测试运行结果。
- 在没有真实设备测试和场地核验前，不应将示范包的 GPS 点位、图片分享或完整游戏流程标记为正式可用。

## 建议验收顺序
1. 先用不含媒体的小型游戏包生成分享链接，在另一台设备或无痕窗口打开，确认接收端加载的是分享包而不是本机默认包。
2. 添加一张现场照片，检查编辑器是否保留清晰可辨的画面；重复分享并在另一台手机打开，再逐步增加图片数量和文档大小，记录链接长度及接收端表现。
3. 测试复制 JSON 后能否在编辑器内导入；如果没有导入入口，记录为未实现，不用手工粘贴冒充导入功能。
4. 最后再用真实校园照片和现场重新标定的 GPS 点位做整套手机测试。

## 首批验收清单
- [ ] 可编辑情景故事、前往提示、玩家任务指令。
- [ ] 可添加和替换现场图片与题目图片。
- [ ] 可切换选择题、文本答案题、关键词题。
- [ ] 可编辑选项、正确答案或多个可接受答案。
- [ ] 可编辑提示和答对后的故事反馈。
- [ ] 保存后重新打开，内容仍然存在。
- [ ] 手机端试玩时，题目、答案判定、图片和反馈表现正确。
- [ ] 导出再导入后，图片与情景内容保持完整。
- [ ] 真实场地与坐标经过现场核实，任务不要求进入室内。
