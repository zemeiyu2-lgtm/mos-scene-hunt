# MOS Scene Hunt 手机端视觉系统 V1.0（设计提案）

## 目标

让 MOS Scene Hunt 更像成熟、友好、面向全球玩家的户外探索游戏，而不是后台管理系统。界面必须优先适配手机单手操作、户外强光、短时查看和双语文字长度差异。

本文件是视觉方向与实施约束，不代表设计已合并或生产发布。所有代码改动需在独立分支实施并经过自动化测试和手机实测。

## 视觉方向

采用「自然探索 + 清晰任务反馈」：

- 以浅色自然底色作为默认视觉基线，深色夜间主题作为后续可选增强，不在第一轮同时大改所有页面。
- 主色采用森林绿/青绿，表达探索、前进和完成。
- 天空蓝用于地图信息、定位与辅助动作。
- 暖琥珀/橙色只用于提醒、线索重点和需要注意的状态，避免全站按钮都抢眼。
- 适度使用圆角卡片、细边框、柔和阴影；减少过度装饰、渐变堆叠和无意义动画。
- 以真实场景图片和简洁地图标记建立探索感。图片应来自用户授权素材、可合法使用的素材，或后续可替换的占位图；不要把未经许可的图片作为产品依赖。

## 色彩令牌（建议起点）

| 用途 | 建议值 | 使用规则 |
|---|---|---|
| 页面底色 | `#F5F8F6` | 温和的自然浅灰绿 |
| 卡片 | `#FFFFFF` | 主要内容表面 |
| 主色 | `#109B81` | 主要操作、当前导航、成功反馈 |
| 主色深色 | `#08765F` | 深色文字/按压状态需保证对比度 |
| 辅助蓝 | `#3B82F6` | 地图与定位辅助信息 |
| 提醒琥珀 | `#F59E0B` | 提醒、线索强调；不作为大面积底色 |
| 正文 | `#14251F` | 标题和正文 |
| 次要文字 | `#64748B` | 辅助说明、次要元数据 |
| 分隔线 | `#DDE7E2` | 卡片边界与输入框 |

实施时需检查普通文本、按钮文本、状态提示的对比度；不能只凭色值观感判断可读性。状态不能只靠颜色区分，需同时使用文字或图标。

## 字体与排版

- 优先使用系统字体，避免首屏额外下载字体影响加载速度。
- 中文使用系统中文字体回退；英文使用系统无衬线字体。
- 页面主标题约 22–28px，卡片标题 16–18px，正文 14–16px，辅助说明不低于 12px（关键指令优先 14px 以上）。
- 正文行距宽松；长线索允许自然换行，不能固定高度裁掉内容。
- 英文长词、中文按钮和混合数字/单位需检查窄屏表现。
- 关键触控目标建议至少 44×44 CSS px；主要操作按钮高度以 48px 为基线。

## 组件规则

### 按钮
- 主操作：实心主色，页面同一时刻只突出一个主要操作。
- 次操作：白底/透明底、清晰边框。
- 危险操作：仅在确实有破坏性行为时使用危险色，并增加确认。
- 禁用态需清楚表达，不以低对比度导致文字无法阅读。

### 卡片
- 统一圆角、边框、间距与标题层级。
- 首页可以有探索主题视觉；任务、背包、设置页优先信息效率。
- 不把每一条信息都做成独立卡片，避免页面变得过度碎片化。

### 状态
- 待前往、已到达、答题中、已完成、已锁定均需有明确文字标签。
- 定位中、定位失败、无权限、离线等状态应提供下一步操作说明。
- GPS 距离和抵达半径应清晰可见，但不制造「GPS 一定精确」的错误印象。

### 底部导航
- 保持当前产品信息架构，不因为视觉更新增加新导航入口。
- 当前页面有明确选中态，图标和文字同时出现。
- 保留 iOS 安全区域与底部内容间距。

### 图片与图标
- 图标采用统一线性风格，不混用大量 emoji 与不同图标套件。
- 主要动作使用有辨识度的图标，并保留文字标签。
- 图片裁切需有明确焦点；缺图时有稳定占位样式，不影响任务操作。

## 页面优先级

1. **首页**：产品名称、游戏入口、继续游戏/选择游戏、试玩入口和户外安全说明。首屏要让新玩家知道「这是什么、下一步做什么」。
2. **地图**：地图保持最大可用面积；当前位置、目标点、距离和定位状态层级明确；底部信息面板不能遮挡核心地图交互。
3. **任务/挑战**：线索和题目优先；答案选项有足够触控间距；提交后明确反馈，不用纯颜色表达正确与否。
4. **奖励**：庆祝感适度，先说明完成了什么，再展示奖励和下一步。
5. **背包**：清楚展示物品名称、数量和用途，避免过度游戏化装饰降低可读性。
6. **设计器**：优先让创建流程清楚、字段易编辑、保存与分享状态可见；不要为了视觉效果增加复杂步骤。

## 国际化与内容边界

- UI 语言（英文/简体中文）与创作者编写的游戏内容语言继续分离。
- 切换 UI 语言不能翻译或覆盖标题、线索、答案、奖励、游戏包或存档。
- 任何新 UI 文案必须同时补充英文与简体中文字典项。
- 不把「自然探索」的视觉风格强加给每个游戏主题。界面框架保持一致，具体游戏可通过封面图、主题色、图标和内容呈现个性化。

## 分阶段实施

### 阶段 A：低风险视觉统一
- 校准 CSS 设计令牌、按钮、卡片、输入框、状态标签、导航选中态。
- 优先改首页与任务页，再扩展到地图、奖励、背包、设计器。
- 不改变路由、游戏逻辑、GPS 算法、数据结构、存档键、游戏包格式或分享协议。

### 阶段 B：页面精修
- 调整首页信息层级与探索视觉。
- 优化地图上的目标卡片与定位状态。
- 优化任务、奖励和背包的状态反馈与空状态。
- 检查中英文长短差异和小屏溢出。

### 阶段 C：深色模式（单独评估）
- 先检查现有页面是否已有可复用的主题机制。
- 只有在浅色主题稳定、关键对比度与手机验收通过后，再做完整深色模式。
- 不把静态设计稿中的深色样式当成已经实现的功能。

## 验收标准

- TypeScript 检查、单元测试、生产构建和现有端到端验收全部通过。
- 英文与简体中文均无溢出、遮挡或按钮截断。
- 主要触控目标易于点击，底部导航不遮挡内容。
- 无障碍状态不仅靠颜色表达，关键文字对比度可读。
- 切换语言不影响 GPS、游戏内容、进度、背包、奖励、存档或分享数据。
- 实机检查首页、地图、挑战、奖励和背包；真实 GPS 相关结论必须来自户外手机测试。
- 不合并到生产分支，直到相关验收记录完成。
