# 权限矩阵与安全实现说明（V1）

本文件列出**每个入口实际要求的权限**，以及对应代码位置。判断标准是「服务端校验」，
不是「界面是否显示按钮」——界面上隐藏按钮只是便利，不构成边界。

---

## 1. 角色与能力

| 能力 | creator | reviewer | admin |
|---|---|---|---|
| 提交游戏包（首个版本 / 后续版本） | ✅ 仅限自己名下作品 | ⚠️ 同 creator（不因角色扩大归属权） | ⚠️ 同上，**不能**用他人 `gameId` |
| 查看自己的作品与版本 | ✅ | ✅ | ✅ |
| 预览任意作品版本（含未审） | ❌ | ✅ | ✅ |
| 领取审核 / 提交审核决定 | ❌ | ✅ | ✅ |
| 发布上线 / 撤下 / 下架 / 恢复 / 归档 | ❌ | ❌ | ✅ |
| 转移作品归属 | ❌ | ❌ | ✅ |
| 创建账号 / 改角色 / 停用 | ❌ | ❌ | ✅ |
| 导入历史作品 | ❌ | ❌ | ✅ |
| 查看审计日志 | ❌ | ✅（后台页） | ✅ |
| 公开读取已上线作品 | 匿名可读（`published` / `unlisted`） | | |

角色等级 `creator(1) < reviewer(2) < admin(3)`，`requireRole(request, "admin")` 实际是
`ROLE_RANK[user.role] >= ROLE_RANK["admin"]`，避免「多写一个角色就漏一处」。见 `lib/auth/guard.ts`。

## 2. 端点逐个对照

| 方法 | 路径 | 要求 | 服务端校验位置 |
|---|---|---|---|
| POST | `/api/auth/login` | 匿名 | 限流 + 失败计数 + 锁定（`lib/auth/handlers.ts`） |
| POST | `/api/auth/logout` | 任意会话 | 撤销当前 token（`revokedAt`） |
| GET | `/api/auth/me` | 任意会话 | 返回 `PublicUser`，不含散列 |
| POST | `/api/publish` | 登录 + 归属 | `requireUser` → `assertSafeMutation` → 限流 → `canClaimGameId` |
| GET | `/api/games/{id}` | **匿名** | registry 状态闸门：非 `published`/`unlisted` → 404 |
| POST | `/api/admin/works/{id}/claim` | reviewer+ | `requireRole(reviewer)` + `assertSafeMutation` |
| POST | `/api/admin/works/{id}/decision` | reviewer+ | 同上；非 approve 必须带原因码 |
| POST | `/api/admin/works/{id}/publish` | admin | `requireRole(admin)`（**先于**读取作品） |
| POST | `/api/admin/works/{id}/{withdraw,unlist,restore,archive}` | admin | 同上 |
| POST | `/api/admin/works/{id}/transfer` | admin | 同上 + 目标账号必须存在且 `active` |
| GET | `/api/admin/preview/{id}/{v}` | 本人 或 reviewer+ | 无权者返回 404（与不存在同体，归属不可探测） |
| GET/POST | `/api/admin/users` | admin | `requireRole(admin)` |
| PATCH | `/api/admin/users/{id}` | admin | 同上；角色变更即时失效该用户会话 |
| POST | `/api/admin/import-legacy` | admin | 同上 + `assertSafeMutation`；默认演练 |

后台页面（`/admin/**`）在 `layout.tsx` 里 `requirePageSession()`，未登录重定向到
`/admin/login`；页面内再按角色决定展示哪些操作。**页面渲染从不作为授权依据**。

## 3. 会话与口令

| 项 | 实现 |
|---|---|
| 口令散列 | scrypt（N=2^14, r=8, p=1, keylen=64, salt 16B），`lib/auth/password.ts` |
| 会话存储 | 只存 `sha256(token)`，库泄露也不可直接冒用 |
| Cookie 名 | 生产 `__Host-mos_sess`（强制 Secure、Path=/、无 Domain）；开发 `mos_sess` |
| Cookie 属性 | `HttpOnly`、`SameSite=Lax`、`Secure`（生产） |
| 有效期 | 创作者 7 天；reviewer/admin 8 小时 |
| 登出 | 写入 `revokedAt`，之后 `verifySession` 拒绝 |
| 角色变更 | 立即撤销该用户全部会话（权限不能靠旧 token 续命） |
| 爆破防护 | 失败计数持久化 + 15 分钟锁定；未知邮箱走 dummy hash 等时校验（不泄露账号是否存在） |
| 令牌比较 | 定长哈希后比较，避免时序差异 |

**实现期发现的真实缺陷（已修）**：`guard.currentSession` 起初只读 `mos_sess`，而生产环境签发
`__Host-mos_sess`，导致生产构建下**所有受保护接口 401**，而单测环境（无前缀）全绿。
修复后补了回归测试「accepts the production `__Host-` cookie name」，
并在 Preview 真实 HTTPS 上跑通（见在线验收记录）。

## 4. CSRF

所有变更类接口（POST/PATCH）过 `assertSafeMutation()`：

1. `Content-Type` 必须含 `application/json`（阻断表单/`text/plain` 简单请求）；
2. `Origin` 必须与 `Host` 同源（缺失或跨站 → 403）。

`SameSite=Lax` 是第二层；两层独立生效，任一层被绕过仍有另一层。

## 5. 原 P0 漏洞与关闭证据

| P0 | 原状 | 现状 | 证据（真实 HTTP） |
|---|---|---|---|
| 匿名写入 | `POST /api/publish` 无任何身份 | `requireUser`，匿名 401 | e2e「匿名提交被拒绝（401）」 |
| 归属伪造 | 以客户端自选 `game.id` 直接写入 | 已存在且非本人 → 403 `game_id_taken` | e2e「他人（含管理员）用同一 id 提交被拒绝（403）」 |
| `latest` 指针污染 | `publish()` 直接把 `latestVersionId` 指向最新写入 | 公开读只认 `publishedVersionId`；发布是独立授权动作 | e2e「审核通过但未发布时公开读取仍 404」「新版本待审期间仍是首版」 |
| 未审内容可读 | `GET /api/games/{id}` 无状态闸门 | 非 `published`/`unlisted` 一律 404（含 `?v=`） | e2e「未审核作品公开读取 404」 |
| 无撤回 | 只能覆盖 | `withdraw` → 404；`restore` → 恢复原版本 | e2e「撤下后 404」「恢复后内容一致」 |
| 无审计 | 无 | 每次状态变更写审计，后台可查 | e2e「审计页包含发布记录」 |

## 6. 并发与幂等

| 场景 | 期望 | 实测（`tests/registry/concurrency.test.ts`） |
|---|---|---|
| 两账号抢同一 `gameId` | 只有一个成功 | `[201, 403]`，作品文档唯一 |
| 同作者两路并发提交 | 两个版本都保留 | `[201, 201]`，版本数 2 |
| 两路矛盾审核决定 | 只落一条 review | `[200, 409]` |
| 重复提交相同内容 | 幂等 | 返回同 `versionId`，不新增版本 |
| 同一请求重试（网络抖动） | 不产生不可控冲突 | 同上；版本对象内容寻址，重写即同字节 |

## 7. 明确未做（不宣称已做）

- **多实例分布式限流**：当前限流为单实例内存，多实例部署会被放大 N 倍。真正的爆破防线（持久化失败计数 + 锁定）不受影响。
- **邮件通知**（审核结果、账号邀请）：无邮件 SDK，未实现；审核结果在后台页面可见。
- **双因素认证**：未实现。
- **作品认领（作者自助认领历史作品）**：当前只能由管理员用「转移归属」指派，没有自助认领流程。
