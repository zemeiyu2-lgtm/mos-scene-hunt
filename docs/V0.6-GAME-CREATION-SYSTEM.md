# MOS Scene Hunt V0.6｜游戏设计与内容包系统

## 产品定位

MOS Scene Hunt 是**手机优先的真实世界游戏平台**。

- 手机：完整游戏体验，也具备完整的基础创作能力。
- 电脑：增强型创作端，用于更大的地图、更高效的内容编辑与导入导出。
- 手机和电脑使用同一个 Game Package，不开发两套游戏。

核心原则：

> 手机优先，电脑增强；一个游戏包，跨设备设计与运行。

## V0.6 目标

从“可以玩的 GPS 寻宝游戏”升级为：

> 可以设计、保存、导入、导出、验证并运行大量独立游戏内容的现实世界游戏平台。

四层：游戏引擎、空间设计、游戏内容、游戏包。

## 空间设计

空间设计是核心创作层，不是内容完成后的附加设置。

必须保留 V0.4 的手动地图创作：地图、划定探索区域、添加/拖动/删除点位、设置 GPS、设置触发半径、地图点击放置、使用当前位置、显示探索区域、调整点位顺序。

V0.6 增强：探索区域中心/半径/边界/实时尺寸；路线 ①→②→③；相邻点距离；总距离；粗略步行时间；空间警告（点位出界、点位过近、触发圈重叠、异常距离、起终点问题、缺少 GPS）。警告不得自动修改设计者决定。

V0.6 继续使用圆形探索区域；不强制升级为多边形。

## 游戏内容

每个场景至少包含：地点、希望玩家发现什么、现场观察、故事、行动、任务、完成条件、奖励、下一站。

保留既有 choice、keyword、text、briefing、explanation、hint、image、PDF/Word/PowerPoint media、sound、reward。

## 游戏设计模板

提供人类可读的 MOS Scene Hunt Game Design Template。

首选格式：Markdown、JSON。

模板包括：游戏名称、目的、目标玩家、玩家人数、预计时间、游戏类型、主题、探索区域、起点、终点、路线、点位，以及每站的地点/发现/观察/故事/行动/任务/完成条件/奖励，最终体验与结束信息。

BSOP《神学院的八个秘密》作为第一标准示范包。

## Game Package

独立游戏包结构：

```
Game Package
├── game metadata
├── spatial
├── scenes
├── challenges
├── rewards
├── media references
└── version info
```

引擎不得因为主题不同而修改。

## 导入导出

V0.6 第一阶段：

设计 → 导出 → 导入 → 结构检查 → 空间检查 → 内容检查 → 预览 → 试玩。

必须支持 JSON 导入、JSON 导出、复制游戏、手机导入/导出、电脑导入/导出。

## 验证

导入后检查：数据（ID、名称、场景、任务、奖励）；空间（GPS、探索区域、点位、路线、触发半径）；游戏逻辑（起点、顺序、解锁、完成、奖励、最终结束）；媒体（图片、文件、URL、media reference）。

结果明确为“可以试玩”或“需要修正的问题列表”。

## 创作模式

### 手机
完整基础创作：地图 → 区域 → 点位 → 内容 → 保存 → 导入/导出 → 验证 → 试玩。

### 电脑
增强创作：更大的地图、更方便的文字输入、更高效的批量编辑、导入导出。

### AI
V0.6 暂不实现 AI 自动生成系统，但 Game Package 保持未来可接入 AI 的结构。

## 游戏库

V0.6 建立本地游戏库概念：游戏名称、封面、描述、类型、时间、难度、版本、状态。

状态：draft / validated / published。

暂不实现账号、云端多人、市场等。

## 媒体

当前本地媒体机制继续保留。架构允许 game JSON → mediaId → object storage/CDN。

V0.6 不实现完整云端媒体系统。

## 明确不做

账号、云数据库、实时多人、聊天、AR/WebXR、AI 自动生成系统、AI 自动找 GPS 点、支付、实体奖励后台、社区、游戏市场、复杂权限。

## V0.6 验收

设计者能够：手机或电脑打开设计器；划定真实探索区域；放置至少 8 个点；调整路线和触发半径；编写内容；保存；导出游戏包；删除/复制游戏；重新导入；自动验证；试玩；使用同一个游戏包获得与原有游戏一致的手机运行体验。

满足以上条件，V0.6 完成。
