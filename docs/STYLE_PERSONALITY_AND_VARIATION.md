# MOS Scene Hunt：产品气质与可控随机风格

## 这款产品应该给人的感觉

MOS Scene Hunt 不应像企业管理后台，也不应像把所有页面都做成霓虹色、弹窗和积分的竞技手游。它是一款把人带到真实世界、鼓励观察、探索、解谜和分享的手机游戏。

核心气质建议定为：

- **好奇，但不浮夸**：让人想点开、想走出去看看，不靠满屏特效制造刺激。
- **亲切，但不幼稚**：青年、家庭、学生、成人都能使用；避免过分卡通化，也避免冷冰冰的工具感。
- **有发现感，但不混乱**：线索、地图标记、揭晓和奖励可以有惊喜；导航、文字、按钮始终清楚。
- **轻盈、真实、包容**：户外使用优先，阳光下易读，单手操作顺畅；不同文化和不同游戏主题都能承载。
- **创作者有自由，玩家不用重新学习**：每个游戏可以拥有自己的气氛，但基本操作的位置和反馈方式保持熟悉。

一句话：**像一本可以走进去的探索故事，而不是一套固定皮肤的表单，也不是不断闪烁的游乐场。**

## 随机风格：不随机改变一切

完全随机地更换字体、按钮、导航、布局和颜色，会破坏可用性、品牌辨识度和中英文适配；每次打开都变，也会让玩家难以建立肌肉记忆。因此建议采用「稳定骨架 + 可变氛围」：

### 始终固定的产品骨架

- 导航位置、页面层级、返回方式和主要操作位置。
- 文字层级、可点击区域、按钮状态、表单行为和错误提示。
- GPS、地图、任务进度、背包、奖励、存档、分享与离线逻辑。
- UI 语言和游戏内容语言相互独立。
- 颜色不能成为表达状态的唯一方式；关键状态要有文字或图标。

### 可以变化的视觉层

- 游戏封面图、背景纹理、主题插画和场景图片。
- 一组受约束的主题色与辅助色。
- 任务卡片的装饰、地图点位的外观、奖励揭晓动效。
- 内容语气和故事氛围由创作者决定，不由 UI 随机翻译或改写。

## 建议的第一批风格家族

这些是可供创作者选择或系统抽取的方向，不代表现在已经全部实现：

1. **自然远征**：森林绿、天空蓝、地图纹理、轻量路线感。作为默认风格，适合城市探索、户外任务、教育活动。
2. **故事手账**：暖白、纸张质感、墨色标题、手绘线索。适合历史、文化、博物馆与亲子探索。
3. **城市侦探**：石墨灰、路标黄、简洁网格、线索标签。适合解谜、寻宝和城市任务。
4. **奇想冒险**：更鲜明的宝石色、章节插画和有限的揭晓动画。适合幻想故事和年轻玩家，但仍保留清晰导航。
5. **安静发现**：低饱和自然色、留白和低动效。适合自然观察、反思式任务和长时间户外活动。

不要把主题与内容类型硬绑定；创作者可以为任何游戏选择任意风格。首版先实现 2–3 套经过检查的风格，比做大量不受控的随机组合更可靠。

## 随机策略建议

- 首次创建游戏时，可以随机推荐一种风格；创作者能预览、重新抽取和手动选择。
- 对同一个游戏，抽取结果应保存到游戏包中；重新打开、分享给别人或离线游玩时，风格不应自行改变。
- 如果未来加入「每次开新游戏随机风格」，随机对象只应是已审核的风格预设，不是随意拼接每个 CSS 属性。
- 不随机更改正文对比度、字体可读性、按钮位置、地图操作、无障碍设置或减少动态效果偏好。
- 游戏内容包没有指定风格时，回退到稳定的「自然远征」默认风格。
- 风格预设是表现层元数据，不得更改坐标、任务条件、答案、奖励、存档结构或分享协议。

## 实施顺序

1. 完成现有浅色基础主题的一致性与对比度检查。
2. 选首页、任务页和奖励页做静态风格对照，先确认差异是否真的有价值。
3. 将风格收敛为少量主题令牌与可替换装饰层，不复制整套页面。
4. 加入创作者预览与选择；确认保存和分享后仍保持相同风格。
5. 再评估随机推荐、更多主题和动态效果。

## 验收问题

- 玩家能否在几秒内看懂下一步做什么？
- 在手机阳光下，正文、按钮和 GPS 状态是否清楚？
- 英文与简体中文换行后是否仍然自然？
- 同一游戏在两台手机上是否保持一致？
- 换风格是否只改变视觉，不影响任务与存档？
- 主题是否让游戏更有气氛，而不是增加视觉噪音？

## 当前范围说明

本文件是设计原则和后续实施依据，不表示随机风格功能已经上线。先用受约束的预设做出稳定体验，再根据实际玩家反馈决定是否增加随机化。
