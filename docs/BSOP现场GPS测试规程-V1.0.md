# BSOP 现场 GPS 测试规程 V1.0

## 目的

BSOP 是 MOS Scene Hunt 的现场测试场地与示范游戏，不是需要冻结内容的母版。允许为了验证定位、触发、地图、语音和任务流程而调整站点内容。

本规程用于区分「坐标配置正确」「手机定位足够稳定」与「游戏触发逻辑正确」，避免只凭地图视觉效果判断功能通过。

## 测试前准备

- 使用实际参加游戏的手机和浏览器；记录手机型号、系统、浏览器及是否从主屏幕打开。
- 开启定位权限，并允许浏览器使用精确位置（若系统提供该选项）。
- 在户外开放区域测试；先停稳再看屏幕，不要边走边操作。
- 确认测试点是现场实测点，不把仓库中的示范坐标直接视为准确坐标。
- 记录当天环境：室外/室内、天空遮挡、附近高楼或屋檐等。

## 每个站点的现场标定

1. 到达预定的可安全停留位置。
2. 停止移动，等待定位读数稳定；记录手机报告的经纬度与水平精度（accuracy，单位米）。
3. 将当前实测位置设为站点坐标；记录站点名称、坐标、日期、设备和精度。
4. 从可安全通行的方向逐步接近站点，记录显示距离和触发时刻。
5. 离开触发范围再返回，至少重复三次。
6. 检查到站反馈、场景解锁、任务完成、奖励和下一站指引是否一致。
7. 若触发忽早忽晚，先检查定位精度和坐标，再检查触发半径与判定逻辑；不要一开始就把半径无限放大。

## 触发半径测试

可依次测试 10、15、20、30 米；若现场 GPS 波动较大，再测试 50 米作为对照。最终半径应根据现场实测决定，而不是所有站点一律使用同一数值。

每轮至少记录：

| 项目 | 记录内容 |
|---|---|
| 站点 | 站点名称/编号 |
| 实测坐标 | 纬度、经度 |
| 手机定位精度 | accuracy，米 |
| 设定触发半径 | 米 |
| 接近时显示距离 | 米 |
| 实际触发位置 | 现场描述或地图点 |
| 结果 | 正常 / 过早 / 过晚 / 未触发 / 误触发 |
| 重复次数 | 例如 1/3、2/3、3/3 |
| 备注 | 建筑遮挡、定位跳动、浏览器等 |

## 验收标准

- **坐标可追溯：** 每个测试点注明「现场实测」或「待标定」，不将近似坐标写成精确位置。
- **重复性：** 同一站点从相近路线接近三次，触发结果可解释；偶发偏差要有记录。
- **无明显误触发：** 尚未接近站点时，不应因单次定位跳点而连续解锁多个站点。
- **反馈一致：** 地图上的距离、到站状态、场景页面和奖励状态一致。
- **容错透明：** 当手机定位精度差或读数不稳定时，界面应提示用户等待/移动到开阔处，而不是假装定位精确。
- **安全优先：** 不要求用户进入私人区域、限制区域、道路或不安全位置来触发站点。

## 解释边界

手机 GPS 的 accuracy 是系统估算值，不是对真实误差的绝对保证。室内、建筑遮挡、树荫和设备差异都可能影响定位。现场测试用于找出可接受的体验范围，不应承诺厘米级或始终固定的触发精度。
